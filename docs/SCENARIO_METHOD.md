# Scenario method: how every number is calculated

Code: `src/lib/geo.ts` (geometry) and `src/lib/scenario.ts` (scenario engine). Tests: `src/lib/__tests__/`.

## 1. Inputs

| Input | Source |
|---|---|
| Existing facilities | `src/data/kanalatlas-data.json`, built from the OSM extract by `scripts/build-dataset.ts` |
| Category | `swimming` **or** `park`. They are never mixed. |
| Data scope | `core`: named or explicitly tagged records (parks: named or ≥ 5,000 m²). `all`: adds the unnamed “extended” records. Records with `access=private/customers` are **never** used. |
| Threshold | Straight-line distance in metres (swimming: 500/1000/1500/2000; park: 200/300/500/800) |
| Hypothetical facilities | Up to 3, placed by the user inside the analysis box |

## 2. Sample points (not people)

`generateEvaluationGrid(bbox, 500)` places a regular grid with 500 m spacing, centred in the analysis box. The box is about 5,504 m wide and 2,557 m tall, which gives 12 columns × 6 rows = **72 points**. Rows are lettered A (north) to F (south) and columns numbered 01 (west) to 12 (east).

Each point also stores:
- `nearLabel`: the name of the nearest OSM neighbourhood centroid. This is a label only.
- `canalDistanceM`: the shortest straight-line distance to any mapped canal segment (point-to-segment, in a local flat projection).

## 3. Distance: the Haversine formula

For points 1 and 2 with latitude φ and longitude λ in radians:

```
a = sin²(Δφ/2) + cos φ1 · cos φ2 · sin²(Δλ/2)
d = 2R · asin(√a),   R = 6,371,008.8 m
```

This is the great-circle (“as the crow flies”) distance. **It is not walking distance.** It ignores roads, bridges, the canal itself and other barriers, so a real walk is always at least this long and often longer.

Why Haversine rather than a road network? It is exact for straight-line distance, has no dependencies, is reproducible by hand, and is honest about what it measures. Pedestrian routing (for example OSRM or Valhalla on OSM roads) would be more realistic. It would also add a server or a heavy client graph and new failure modes, and it is the top item in `submission/FUTURE_WORK.md`.

## 4. Nearest facility, before and after

For each point *p*:

1. **before** = the nearest active existing facility (ties are broken by facility id, so the result is deterministic even with duplicate coordinates).
2. The nearest hypothetical facility of the same category is found.
3. **after** = that hypothetical facility **only if strictly closer** than *before*; otherwise *before*.
4. **Δ** = after − before (≤ 0). If no existing facility is active, *before* is undefined, Δ is undefined, and the point is counted in `newlyDefined`. **No percentage change is ever computed from an undefined baseline.**

## 5. Summary metrics

Computed over points with a defined distance:

- `withinCount`: points with distance ≤ threshold (inclusive)
- `meanM`, `medianM`, `maxM`
- `withinGained` = after.withinCount − before.withinCount
- `pointsImproved`: points with Δ < 0
- `largestImprovementM`
- **Canal belt:** the same metrics for points ≤ 500 m from a mapped canal segment (27 of 72 points)

`meanDeltaM` is only reported when before and after are defined for the same number of points.

## 6. Worked example you can redo with a calculator

Settings: swimming, core scope, 1 km threshold. Point **A12** (north-east corner, labelled “Kışla”) is at 37.021742, 35.329976.

**Before.** The distances to the five core facilities are 3,503.8 m (Hayal Park), 5,873.1 m (Adana BB Kapalı Yüzme Havuzu), 4,811.7 m (Yüzme Havuzu), 3,959.2 m (Pınar Yüzme Havuzu) and **3,423.1 m** (unnamed pool at 37.021282, 35.291423). The nearest is the last one, so before = 3.42 km, which is outside 1 km.

**After** adding a hypothetical pool at 37.0105, 35.3205 (Location A):

```
φ1 = 37.021742° = 0.646151293 rad      φ2 = 37.0105° = 0.645955083 rad
Δφ = −0.000196210 rad                  Δλ = (35.3205 − 35.329976)° = −0.000165387 rad
a  = sin²(−0.000098105) + cos(0.646151293)·cos(0.645955083)·sin²(−0.0000826937)
   = 9.6246e-9 + 0.79840 · 0.79852 · 6.8383e-9 ≈ 1.39843e-8
d  = 2 · 6,371,008.8 · asin(√1.39843e-8) = 2 · 6,371,008.8 · 0.000118255 ≈ 1,506.8 m
```

1,506.8 m < 3,423.1 m, so after = 1.51 km (the hypothetical pool). Δ = −1,916 m, shown as “−1,92 km”. The point is still outside 1 km, so it counts in `pointsImproved` but not in `withinGained`. The full per-point table is in `docs/PROOF_RUN_OUTPUT.md`, generated by `npm run proof`.

## 7. “Where would one facility help most?”

`suggestSites` screens every point of a **100 m candidate grid** (1,456 candidates). For each candidate *c* it counts the sample points that would newly fall within the threshold if *c* were built (gain), plus the total distance reduction. Candidates are ranked by gain, then mean reduction (rounded to 0.1 m), then id. The top 3 are kept, at least one threshold apart. Cost is O(candidates × points), about 13 ms in Node.

It is a **screening heuristic on sampled points**. It does not know about land ownership, cost, buildability or demand.

## 8. Comparing locations A and B

Saved scenarios store only their hypothetical coordinates. The comparison table **re-evaluates every saved scenario with the current category, scope and threshold**, so A and B are always compared with one method. “Best” means more points within the threshold, with a lower mean distance breaking ties. That is a ranking rule, not a recommendation.

## 9. Validation and edge cases (all unit-tested)

| Case | Behaviour |
|---|---|
| Zero facilities in category/scope | Baseline undefined; no mean change; note shown |
| Single facility / duplicate coordinates | Deterministic tie-break by id |
| Hypothetical on top of an existing facility | Ties keep the existing one → “no change” note; a ≤ 30 m warning on placement |
| Invalid coordinates (NaN, out of range, strings) | Rejected (`isValidLatLon`) |
| Placement or drag outside the analysis box | Rejected with a Turkish message; a dragged marker snaps back |
| Missing metadata (no name) | Shown as “İsimsiz kayıt” |
| Zero distance | Counted as within the threshold |
| Category mixing | Impossible: facilities and hypotheticals are filtered by category |
